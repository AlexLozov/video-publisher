# Правила проекта

## Разработка

- Каждая фича и каждый баг делаются в отдельной ветке от `main`.
- Коммиты небольшие и логичные, сообщения на английском в стиле conventional commits (`feat: ...`, `fix: ...`, `docs: ...`).

## Тесты

- Каждая фича и каждый исправленный баг приходят вместе с тестами. Без тестов задача не считается готовой.
- Проверяем все сценарии, а не только успешный:
  - ошибки и некорректные данные;
  - граничные значения (размер и длительность видео, лимиты текста);
  - недоступность сети или платформы, истёкшие токены;
  - отложенная публикация и повторные попытки.
- Бэкенд тестируем через pytest. Внешние API платформ в тестах подменяем заглушками, реальных запросов в соцсети не делаем.
- Интерфейс тестируем через Vitest и Testing Library: компоненты, состояния загрузки и ошибки, переключение языка.
- Покрытие измеряется (pytest-cov, Vitest coverage). Цель — не меньше 85% для ядра и адаптеров.
- Перед каждым коммитом всё должно быть зелёным: pytest, ruff, mypy, тесты интерфейса и `npm run build`.

## Язык интерфейса

- Язык интерфейса пользователь выбирает в самом приложении. Выбор сохраняется между запусками.
- Сначала поддерживаем два языка: русский (по умолчанию) и английский.
- Все тексты интерфейса берутся из файлов переводов, а не пишутся прямо в компонентах. Тогда новый язык добавляется одним новым файлом перевода.
- Сообщения, которые бэкенд показывает пользователю (например, ошибки проверки видео), тоже должны переводиться.
