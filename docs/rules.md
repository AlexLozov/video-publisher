# Правила проекта

## Разработка

- Каждая фича и каждый баг делаются в отдельной ветке от `main`.
- Коммиты небольшие и логичные, сообщения на английском в стиле conventional commits (`feat: ...`, `fix: ...`, `docs: ...`).

## Тестирование — по важности

- Каждая фича и каждый исправленный баг приходят вместе с тестами. К каждому исправлению бага обязательно добавляем регрессионный тест, который ловит именно этот баг.
- **Критичная логика — тестируем все сценарии.** Это публикация (адаптеры площадок), расписание, секреты и миграции базы. Проверяем:
  - успешный путь;
  - ошибки площадок: нет сети, истёк токен, API вернул отказ, исчерпан лимит или квота, повторные попытки, обрыв во время загрузки;
  - неверные данные: формат, размер или длительность видео, длина текста;
  - расписание: время в прошлом, часовые пояса, перезапуск приложения при запланированных публикациях;
  - что секреты не попадают в базу, ответы API и логи;
  - что миграции сохраняют данные и модели совпадают с миграциями.
- **Интерфейс — только ключевые сценарии.**
  - Vitest и Testing Library: основные состояния экранов — загрузка, успех, ошибка, пустой список.
  - Playwright: один сквозной тест на экран, на одном языке (русском), через настоящий бэкенд.
  - Переводы проверяются не e2e-тестами, а юнит-тестом: одинаковые ключи и подстановки во всех языках, плюс тест, что у каждого кода ошибки бэкенда есть перевод.
- Python: pytest и pytest-cov. Порог покрытия — 85%. Это минимум, гнаться за 100% не нужно.
- HTTP-запросы к площадкам в тестах идут только через моки (respx). В e2e — через локальный поддельный сервер (`tests/fake_telegram_server.py`). Реальные вызовы API бывают только в отдельных интеграционных тестах, помеченных маркером. По умолчанию они не запускаются.
- Ветку можно сливать в `main`, только если проходит `scripts\check.ps1`: ruff, mypy, pytest с порогом покрытия, Vitest, `npm run build`, Playwright.

## Язык интерфейса

- Язык интерфейса пользователь выбирает в самом приложении. Выбор сохраняется между запусками.
- Сначала поддерживаем два языка: русский (по умолчанию) и английский.
- Все тексты интерфейса берутся из файлов переводов, а не пишутся прямо в компонентах. Тогда новый язык добавляется одним новым файлом перевода.
- Сообщения, которые бэкенд показывает пользователю (например, ошибки проверки видео), тоже должны переводиться.
