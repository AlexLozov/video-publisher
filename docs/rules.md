# Правила проекта

## Разработка

- Каждая фича и каждый баг делаются в отдельной ветке от `main`.
- Коммиты небольшие и логичные, сообщения на английском в стиле conventional commits (`feat: ...`, `fix: ...`, `docs: ...`).

## Тестирование

- Каждая фича и каждый исправленный баг приходят вместе с тестами. Без тестов задача не считается готовой. К каждому исправлению бага обязательно добавляем регрессионный тест, который ловит именно этот баг.
- Проверяем все сценарии, а не только успешный:
  - успешная публикация;
  - ошибки площадок: нет сети, истёк токен, API вернул отказ, исчерпан лимит или квота, повторные попытки;
  - неверные данные: неподходящий формат, длина, размер или длительность видео, пустой или слишком длинный текст;
  - расписание: время в прошлом, разные часовые пояса, перезапуск приложения при запланированных публикациях.
- Python: pytest и pytest-cov. Покрытие ядра и адаптеров — не ниже 85%.
- HTTP-запросы к площадкам в тестах идут только через моки (respx). Реальные вызовы API бывают только в отдельных интеграционных тестах, помеченных маркером. По умолчанию они не запускаются.
- Интерфейс:
  - компоненты, состояния загрузки и ошибки, переключение языка — Vitest и Testing Library;
  - ключевые сценарии от начала до конца (выбор ролика → площадки → расписание → публикация) — Playwright, на обоих языках интерфейса.
- Ветку можно сливать в `main`, только если ruff, mypy, все тесты (pytest, Vitest, Playwright), `npm run build` и порог покрытия проходят.

## Язык интерфейса

- Язык интерфейса пользователь выбирает в самом приложении. Выбор сохраняется между запусками.
- Сначала поддерживаем два языка: русский (по умолчанию) и английский.
- Все тексты интерфейса берутся из файлов переводов, а не пишутся прямо в компонентах. Тогда новый язык добавляется одним новым файлом перевода.
- Сообщения, которые бэкенд показывает пользователю (например, ошибки проверки видео), тоже должны переводиться.
