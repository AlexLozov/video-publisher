# Статус проекта Video Publisher

_Обновлено: 7 ноября 2026._

## Коротко

В `main` — рабочее десктопное приложение (Python + React в окне pywebview). Оно публикует MP4-видео в Telegram-канал двумя способами: через бота или от имени вашего аккаунта, с отложенной публикацией средствами Telegram. Есть настройки, хранение секретов в Windows, история публикаций и интерфейс на русском и английском. Все проверки (`scripts\check.ps1`) проходят.

## Что сделано (ветки слиты в `main` через `--no-ff`)

| Ветка | Что в ней |
|---|---|
| `feature/project-skeleton` | Каркас: ядро `core/video_publisher` (domain, адаптеры, api), FastAPI, React + Vite + Tailwind, окно pywebview (`desktop/run.py`), документация. |
| `docs/project-rules` | Правила проекта (`docs/rules.md`): ветка на задачу, тесты, языки интерфейса, TikTok — последним. |
| `chore/test-tooling` | pytest-cov (порог 85%), respx, Vitest, Playwright, единый скрипт проверок `scripts\check.ps1`. |
| `feature/ui-i18n` | i18next: русский (по умолчанию) и английский, переключатель языка. Бэкенд отдаёт коды ошибок, а не текст. |
| `feature/settings` | SQLite + SQLAlchemy + Alembic. Экран настроек. Секреты — в Диспетчере учётных данных Windows (keyring), только на запись. Язык хранится на бэкенде. |
| `feature/telegram-bot` | Публикация через Telegram-бота (Bot API, httpx): проверки MP4 и 50 МБ, повторы при сбоях, без повтора при обрыве во время загрузки. Экран «Публикация»: окно выбора файла Windows и перетаскивание, публикация в фоне, история со статусами и ссылками. Таблица `publications`, восстановление после закрытия приложения во время загрузки. |
| `feature/telegram-account` | Публикация от имени аккаунта через Telethon (MTProto) и cryptg. Вход на экране настроек: телефон → код → облачный пароль (2FA); выход. Свои api_id/api_hash, подсказка про my.telegram.org. Сессия (`StringSession`) — в keyring, файлов `.session` нет. Видео MP4 до 2 ГБ. Отложенный пост хранит сам Telegram (до 365 дней) — выйдет при выключенном компьютере. Статус «запланировано на …» в истории. Ошибки кодами: неверный номер/код/пароль, истёкший код, «подождите N с», нет ключей, нет сети, сессия завершена на другом устройстве. |

## Текущее состояние `main`

- Запуск приложения: `cd ui && npm run build`, затем `.venv\Scripts\python.exe desktop\run.py`.
- Данные: `%USERPROFILE%\.video-publisher\app.db`. Секреты — в Диспетчере учётных данных Windows (служба `video-publisher`).
- Что работает:
  - вкладки «Главная», «Публикация», «Настройки»;
  - Telegram в режиме «Бот»: публикация сейчас, видео до 50 МБ;
  - Telegram в режиме «Мой аккаунт»: вход, публикация сейчас или по расписанию, видео до 2 ГБ.
- Ключи (токен бота, api_id, api_hash) вводятся только в приложении, во вкладке «Настройки». `.env` для них не нужен.
- Тесты:
  - pytest — 355 тестов, покрытие около 99,6% (порог — 70%);
  - Vitest — 122 теста;
  - Playwright — 3 сквозных теста; запускаются флагом `-E2E` перед крупными этапами.
- Правило тестирования — «по важности», с облегчением от 7 ноября (см. `docs/rules.md`).

## План следующих веток (по порядку)

1. **`feature/scheduler`** — очередь отложенных публикаций. Следующий этап, **ещё не начат**: владелец попросил остановиться перед ним.
   - если площадка умеет откладывать сама — вызывается её `schedule`;
   - если нет (бот, Instagram, TikTok) — публикует сам планировщик;
   - пробуждение компьютера из сна по таймерам Windows;
   - обработка перезапуска приложения и часовых поясов.
2. **YouTube / Shorts** — OAuth (Desktop app), загрузка через YouTube Data API v3, отложенная публикация через `publishAt`.
3. **Facebook Page + Instagram** — Meta Graph API.
4. **auth-server** — небольшой внешний сервис для OAuth-редиректов и client secret'ов там, где их нельзя держать в десктоп-приложении.
5. **Дизайн** — доработка внешнего вида интерфейса.
6. **TikTok** — отдельной задачей после остальных площадок (долгий аудит Content Posting API).
7. **API-ключ для скриптов и агентов** — финальный этап, после TikTok. Варианты обсудить с владельцем перед началом:
   - HTTP API с ключом на фиксированном порту;
   - плюс MCP-сервер;
   - плюс CLI.

## Открытые вопросы и задачи

- **Первая настоящая публикация.** Ключи у владельца готовы. Ввести их во вкладке «Настройки» (бот: канал и токен; аккаунт: канал, api_id, api_hash, затем вход по коду). Бот или аккаунт должен быть администратором канала с правом публикации. Секреты в чат не присылать.
- **Сессия завершена на другом устройстве.** Сейчас приложение при публикации показывает ошибку «войдите заново» и удаляет недействующую сессию. Уже запланированные посты остаются в канале. Если нужно другое поведение (например, проверка входа при открытии настроек) — решить с владельцем.
- **Статус запланированных постов.** После того как Telegram опубликовал отложенный пост, в истории он остаётся «запланировано на …». Синхронизацию статуса логично сделать в `feature/scheduler`.
- **Размеры кадра в режиме аккаунта.** Без метаданных видео Telethon отправляет размер 1×1 и длительность 0. Telegram обычно определяет их сам, но превью может отображаться хуже. Это часть вопроса про метаданные ниже: варианты — hachoir (чистый Python), ffprobe (внешняя программа) или ничего не делать. Выбирает владелец.
- **Instagram и TikTok**, скорее всего, не умеют отложенную публикацию через API. Тогда понадобится режим «разбудить компьютер из сна». Перепроверить перед этими этапами.
- **YouTube:** пока проект Google не прошёл аудит, загруженные через API видео остаются приватными. Заявку на аудит лучше подать заранее. Лимит — около 6 загрузок в день.
- **Meta:** для полноценного запуска нужны App Review и верификация бизнеса.
- **Форматы:** через бота принимаем только MP4 — это решение владельца (C1). Конвертации видео в приложении нет.
- **Метаданные видео** (длительность, размер кадра) пока не определяются. Понадобятся для проверок YouTube и Instagram (возможно, через ffprobe — согласовать).
- Предупреждение `StarletteDeprecationWarning` в тестах идёт из библиотеки, на работу не влияет.

## Правила работы

- Каждая задача — в своей ветке от `main`. Слияние — через `--no-ff`, только когда `scripts\check.ps1` проходит целиком.
- Remote не настроен, ничего не публикуется во внешние репозитории.
- Перед выбором с реальными альтернативами (библиотека, способ хранения, поведение интерфейса) — сначала варианты с плюсами и минусами владельцу, решение принимает он.
- Отчёты владельцу — коротко, на русском, после каждого шага.
