# Статус проекта Video Publisher

_Обновлено: 9 ноября 2026 (после публикации на Facebook-страницу)._

## Коротко

В `main` — рабочее десктопное приложение (Python + React в окне pywebview). Оно публикует MP4-видео в Telegram-канал двумя способами (через бота или от имени вашего аккаунта, с отложенной публикацией средствами Telegram) и на Facebook-страницу (вход через Facebook, отложенная публикация средствами Facebook). Есть настройки, хранение секретов в Windows, история публикаций и интерфейс на русском и английском. Все проверки (`scripts\check.ps1`) проходят.

Экран «Публикация»: окно выбора файла Windows и перетаскивание, публикация в фоне, история со статусами и ссылками. Таблица `publications`, восстановление после закрытия приложения во время загрузки. |
| `feature/telegram-account` | Публикация от имени аккаунта через Telethon (MTProto) и cryptg. Вход на экране настроек: телефон → код → облачный пароль (2FA); выход. Свои api_id/api_hash, подсказка про my.telegram.org. Сессия (`StringSession`) — в keyring, файлов `.session` нет. Видео MP4 до 2 ГБ. Отложенный пост хранит сам Telegram (до 365 дней) — выйдет при выключенном компьютере. Статус «запланировано на …» в истории. Ошибки кодами: неверный номер/код/пароль, истёкший код, «подождите N с», нет ключей, нет сети, сессия завершена на другом устройстве. |
| `fix/file-picker` | Кнопка «Выбрать видео» не открывала окно: pywebview отвергал фильтр «Видео / Video» из-за косой черты. Фильтр исправлен, при сбое окна показывается ошибка. |
| `feature/settings-accordion` | Компактные настройки: список соцсетей со статусом («Настроено», «Не настроено», «Скоро»), настройки соцсети раскрываются по нажатию. |

| `feature/choose-networks` | При загрузке выбираются соцсети галочками, настроенные отмечены по умолчанию. `POST /api/publications/batch`, общий `batch_id` (миграция 0003). |
| `feature/facebook` | Публикация видео на Facebook-страницу через Meta Graph API (`v24.0`). Решения владельца 9 ноября: вход через Facebook в браузере, загрузка файла одним запросом, только обычное видео (без Reels), Instagram — отдельной веткой позже. В Настройках — App ID и App Secret своего Meta-приложения, кнопка «Войти через Facebook»: браузер → `http://localhost:47615/facebook/callback` → обмен кода на бессрочный токен страницы (в keyring), выбор страницы, если их несколько. Видео MP4 до 1 ГБ. Отложенная публикация средствами Facebook (`scheduled_publish_time`, от 10 минут до 30 дней) — выйдет при выключенном компьютере; удаление записи снимает запланированное видео. Обрыв во время загрузки — `facebook_timeout_uncertain`, без автоповтора (чтобы не было дубля). Недействующий токен удаляется, настройки просят войти заново. «По расписанию» на экране публикации доступно, если все отмеченные соцсети умеют откладывать сами. |
| `feature/history` | История карточками (одна загрузка — одна карточка со всеми соцсетями), удаление с подтверждением (запланированный в Telegram пост при этом отменяется), «Очистить историю» (запланированные остаются), «Сохранить в CSV» (`;`, UTF-8 с BOM — Excel открывает кириллицу). |

## Текущее состояние `main`

- Запуск приложения: двойной щелчок по `Запуск.bat` или ярлыку «Video Publisher» на рабочем столе. Вручную: `cd ui && npm run build`, затем `.venv\Scripts\python.exe desktop\run.py`.
- Данные: `%USERPROFILE%\.video-publisher\app.db`. Секреты — в Диспетчере учётных данных Windows (служба `video-publisher`).
- Что работает:
  - вкладки «Главная», «Публикация», «Настройки»;
  - Telegram в режиме «Бот»: публикация сейчас, видео до 50 МБ;
  - Telegram в режиме «Мой аккаунт»: вход, публикация сейчас или по расписанию, видео до 2 ГБ;
  - Facebook-страница: вход через Facebook, публикация сейчас или по расписанию, видео до 1 ГБ.
- Ключи (токен бота, api_id, api_hash, App ID и App Secret Meta) вводятся только в приложении, во вкладке «Настройки». `.env` для них не нужен.
- Тесты:
  - pytest — 469 тестов, покрытие около 99,4% (порог — 70%);
  - Vitest — 152 теста;
  - Playwright — 3 сквозных теста; запускаются флагом `-E2E` перед крупными этапами.
- Правило тестирования — «по важности», с облегчением от 7 ноября (см. `docs/rules.md`).

## План следующих веток (по порядку)

1. **`feature/scheduler`** — очередь отложенных публикаций. Следующий этап, **ещё не начат**: 7 ноября владелец попросил сначала сделать только правки интерфейса (они выше) и пока не поднимать вопросы планировщика и метаданных видео.
   - если площадка умеет откладывать сама — вызывается её `schedule`;
   - если нет (бот, Instagram, TikTok) — публикует сам планировщик;
   - пробуждение компьютера из сна по таймерам Windows;
   - обработка перезапуска приложения и часовых поясов.
2. **YouTube / Shorts** — OAuth (Desktop app), загрузка через YouTube Data API v3, отложенная публикация через `publishAt`.
3. **Instagram (Reels)** — Meta Graph API, тот же Meta-app и вход, что у Facebook (сам Facebook уже сделан в `feature/facebook`).
4. **auth-server** — небольшой внешний сервис для OAuth-редиректов и client secret'ов там, где их нельзя держать в десктоп-приложении.
5. **Дизайн** — доработка внешнего вида интерфейса.
6. **TikTok** — отдельной задачей после остальных площадок (долгий аудит Content Posting API).
7. **API-ключ для скриптов и агентов** — финальный этап, после TikTok. Варианты обсудить с владельцем перед началом:
   - HTTP API с ключом на фиксированном порту;
   - плюс MCP-сервер;
   - плюс CLI.
8. **Сборка .exe** — самый последний этап, после API-ключа. Приложение запускается двойным щелчком по .exe, без Python и Node. Инструмент выбрать с владельцем прямо перед этапом:
   - PyInstaller + установщик Inno Setup (ярлыки, удаление, автозапуск для расписания);
   - только PyInstaller;
   - Nuitka.

## Открытые вопросы и задачи

- **Первая настоящая публикация.** Ключи у владельца готовы. Ввести их во вкладке «Настройки» (бот: канал и токен; аккаунт: канал, api_id, api_hash, затем вход по коду). Бот или аккаунт должен быть администратором канала с правом публикации. Секреты в чат не присылать.
- **Сессия завершена на другом устройстве.** Сейчас приложение при публикации показывает ошибку «войдите заново» и удаляет недействующую сессию. Уже запланированные посты остаются в канале. Если нужно другое поведение (например, проверка входа при открытии настроек) — решить с владельцем.
- **Статус запланированных постов.** После того как Telegram опубликовал отложенный пост, в истории он остаётся «запланировано на …». Синхронизацию статуса логично сделать в `feature/scheduler`.
- **Размеры кадра в режиме аккаунта.** Без метаданных видео Telethon отправляет размер 1×1 и длительность 0. Telegram обычно определяет их сам, но превью может отображаться хуже. Это часть вопроса про метаданные ниже: варианты — hachoir (чистый Python), ffprobe (внешняя программа) или ничего не делать. Выбирает владелец.
- **Instagram и TikTok**, скорее всего, не умеют отложенную публикацию через API. Тогда понадобится режим «разбудить компьютер из сна». Перепроверить перед этими этапами.
- **YouTube:** пока проект Google не прошёл аудит, загруженные через API видео остаются приватными. Заявку на аудит лучше подать заранее. Лимит — около 6 загрузок в день.
- **Meta:** для полноценного запуска нужны App Review и верификация бизнеса. Пока Meta-приложение в режиме разработки, вход работает только для его администраторов и тестировщиков, а `localhost`-редирект разрешён автоматически.
- **Первая настоящая публикация на Facebook.** Владельцу: тестовая страница, Meta-приложение в режиме разработки с разрешениями `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`; App ID и App Secret ввести в Настройках, нажать «Войти через Facebook». Если Facebook ругается на адрес — добавить `http://localhost:47615/facebook/callback` в «Действительные URI перенаправления OAuth». Порт меняется переменной `VP_FACEBOOK_REDIRECT_PORT`.
- **Facebook, что сознательно не сделано:** Reels страницы; загрузка частями (выбран вариант «одним запросом», лимит 1 ГБ — можно вернуться, если будут обрывы); App Secret пока хранится на компьютере (в keyring) — в коммерческой версии обмен кода перенести на auth-сервер; статус «запланировано → опубликовано» не синхронизируется (как и в Telegram, — в `feature/scheduler`). Окно отложенной публикации взято консервативно (10 мин — 30 дней), источники расходятся — проверить на живом аккаунте.
- **Версия Graph API** зашита как `v24.0` (`platforms/facebook_page.py`). Meta поддерживает версию около двух лет — поднять до окончания поддержки.
- Страница в браузере после входа («вернитесь в приложение») переводится словарём на бэкенде (`auth/facebook_login.py`, `CALLBACK_TEXTS`), так как она вне окна приложения; тест проверяет одинаковые ключи ru/en.
- **Форматы:** через бота принимаем только MP4 — это решение владельца (C1). Конвертации видео в приложении нет.
- **Метаданные видео** (длительность, размер кадра) пока не определяются. Понадобятся для проверок YouTube и Instagram (возможно, через ffprobe — согласовать).
- Предупреждение `StarletteDeprecationWarning` в тестах идёт из библиотеки, на работу не влияет.

## Правила работы

- Каждая задача — в своей ветке от `main`. Слияние — через `--no-ff`, только когда `scripts\check.ps1` проходит целиком.
- Remote не настроен, ничего не публикуется во внешние репозитории.
- Перед выбором с реальными альтернативами (библиотека, способ хранения, поведение интерфейса) — сначала варианты с плюсами и минусами владельцу, решение принимает он.
- Отчёты владельцу — коротко, на русском, после каждого шага.
